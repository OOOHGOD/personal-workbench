## Part 2 · PRD 全文（逐字，对应 prd/PRD.md 正文）

**锚句（逐字保留，全文不改写）**

> 不是「拥有一个个人工作台」，而是「让工作/学习/申请/简历证据能以最低摩擦被记下来，并在早上、日报、月更、截止前自动出现在眼前，且换设备、换账号、平台变更时不会丢」。

### 1. 一句话目标
见锚句。本文档只定义「什么算做到了」，不定义「长什么样、用什么做」。形态是另一个独立决策（Q1），本 PRD 不预设。

### 2. 场景与动线

| # | 时刻 | 触发 | 期望（零点击到达 + 内容已预先生成） |
|---|---|---|---|
| S1 | 早上工作前 | 打开一个约定位置 | 零点击看到今日重点、逾期、卡住、临近截止 |
| S2 | 随时 | 想到一件事 | 一次输入 + 一次确认就记下，不选分类、不事后重抄 |
| S4 | 晚间 | 要写日报 | 出两版：自用版全含；领导摘要不含学习与申请 |
| S6 | 月初 | 到月初 | 零点击看到已生成好的证据清单 + 按用途标记分组的证据段落（Q15=B） |
| S7 | 任何时候 | 想确认没丢 | 一次操作拿到完整可读的全量副本，且做过恢复演练 |
| R1 | 截止前 14 天内 | 到点主动 | 发一封提醒邮件（**唯一保留的主动通道**） |

「学习复盘」不再是独立场景，降为按用途标记筛选的周度回看（Q10）。原「工作过程」场景是功能清单，已删除（Q2）。场景卡编号沿用旧文档 1–7，保留 1/2/4/6/7。

### 3. 验收条目（每条必须能用「是/否」判定）

| AC | 判定标准 |
|---|---|
| AC-01 | 记一条 = 一次输入 + 一次确认；不需先选分类、不需先打开某个页面、不需事后在别处再抄一遍 |
| AC-02 | 同一个事实只存在一份；一条记录可同时带多个用途标记；同一内容不会被录两次 |
| AC-03 | 取任一带有「用于学习统计」或「用于简历」标记的记录生成两版日报：领导摘要中不含该记录内容，自用版含 |
| AC-04 | 一次操作内产出完整、开放格式、可读、可被别处导入的全量快照；且至少做过一次实际恢复演练并能读回 |
| AC-05 | 早上打开约定位置，零点击即可看到今日重点、逾期、卡住、临近截止四类内容 |
| AC-06 | 申请截止 14 天内且状态为进行中的条目被呈现，并按截止日倒计时分级（细则见遗留项 L1） |
| AC-07 | 月初产出「证据清单 + 按用途标记分组的证据段落」，可复制；不产出完整简历文件，不自动改写任何简历文档 |
| AC-08-A | 临近截止时，由外部服务主动发出一封提醒邮件 |
| AC-08-B | 月初零点击即可看到已生成好的证据清单；**不发邮件**（Q15=B 的净结果） |
| AC-09 | 只做 S1/S2/S4/S6/S7 五张场景卡；学习复盘为筛选式回看，不作为独立场景 |

### 4. 失败场景

| 失败 | 对应 AC | 判定 |
|---|---|---|
| 换设备 / 换账号 / 厂商停服 / 断网 → 取不到数据 | AC-04 | 副本须在权限正常时定期产出，不能等出事再导 |
| 忘了打开 → 月更看不到 | **AC-08-B 未覆盖** | 见「已知妥协」 |
| 同一事实被记两次 | AC-02 | 应只有一份 |
| 私密内容混进领导摘要 | AC-03 | 领导摘要应不含 |
| 提醒邮件没发出 / 发错 | AC-08-A | 需有可查的发送记录或失败可见 |

### 5. 非目标

- 不做多人协作、权限体系。
- 不产出完整简历文件、不自动改写简历文档（Q8）。
- 不要求多份副本实时一致（Q7）。
- 不做手机推送（Q13 选 C，不含手机推送）。
- **不做自定义界面**：列为**待定**，不提前锁死（Q1 形态决策后置）。
- 「打开网页即用」「离线可写」「定期手动导出导入」等旧表述不再作为需求。

**已知妥协（必须写成受限妥协，不得写成设计偏好）**
1. 月更（S6 / AC-08-B）不主动推送，回到「忘了打开就看不到」。这正是 Q9 当初答「否」想甩掉的问题；它只在「截止提醒」上被解决，在「月更」上没有。
2. 收缩原因是外部服务的发送能力有开通门槛，属于**工具能力限制，不是用户不需要**。
3. 该取舍**未经真实试用验证**：Q3 原本约定「等用现成工具试过再定」，Q13 已接受 1 天试用，Q15=B 把它跳过了。后续换工具时应复核。
4. 主动邮件通道只剩 A（截止提醒）一类；同类提醒呈现不一致，未来接手者会困惑。

### 7. 零方案评估

定义：「不写任何代码」能否满足，逐条 AC 打勾。AC-01~07、AC-08-A、AC-08-B、AC-09 **全部能**（AC-08-B 为零点击呈现，非主动发信）。

结论：9 类验收条目全部可在零代码前提下满足 →「只有零方案被证伪才进入架构讨论」的条件**未触发**，因此本 PRD 不激活技术架构讨论，形态决策由流程收敛为「不自建前端层」。该结论由用户答案独立推出，不是沿用外部诊断结论。

**注意**：本评估是纸面可行性核对，不是验收。AC-08-A 的发送能力有开通门槛且未经真实试用。

## Part 3 · GLOSSARY 全文（逐字，对应 prd/GLOSSARY.md）

**工作台**: 一套约定：记录什么、何时出现、怎样算没丢。它不指任何界面、页面或程序；形态是另一个独立决策。
_Avoid_: 系统、应用、网站、页面

**记录**: 工作台里最小的事实单元，也是唯一需要保存的东西。同一个事实只存在一份，可以同时用于日报、学习统计与简历；业务类别只是查看它时的筛选方式，不构成另一种东西。
_Avoid_: 条目、任务、表行、日志、分类

**用途标记**: 标注一条记录可用于日报、学习统计或简历的标签。一条记录可以有多个用途标记。
_Avoid_: 分类、类型、字段、表

**自动**: 信息无需人主动查找即可呈现的性质。判定为零点击到达且内容已预先生成；此外允许在约定时刻由外部服务主动发出提醒，具体触发方式与通道见决策记录。
_Avoid_: 定时任务、后台同步、实时一致

**不丢**: 任意时刻都能从单一主副本取得一份完整、开放格式、可读、可被别处导入的全量快照，且该快照能被实际恢复的性质。判定看快照能否恢复，不看多个副本是否实时一致。
_Avoid_: 实时同步、三处一致、离线可用、缓存数据

**证据**: 一条记录被标记为可用于简历时，它所提供的可核实内容；也是月更产出的唯一内容形态。月更只产出证据清单与按用途标记分组的证据段落，不产出完整简历文件。
_Avoid_: 成果、成果条目、月度成果清单、简历增量、简历文件

## Part 4 · ADR 0001 全文（逐字，对应 prd/decisions/0001-不自建前端层.md）

**status: accepted ｜ date: 2026-11-25 ｜ id: 0001**

单人低频的记录/召回需求，历史上被实现成一个需要持续维护、需三处人工同步、绑死单一宿主 SDK 的自绘界面层；2026-11-25 的 PRD 收敛（第 7 节）确认 9 类验收条目全部可在「不写任何代码」前提下满足，闸门未触发，因此决定**停止自建前端层**，形态决策维持后置、不预设界面。理由：继续自建只是重实现现成服务免费提供的记录、视图、筛选、提醒与移动端，而真正要解决的「自动出现在眼前、换平台不丢」恰是自建层最防不住的部分。

**Considered Options**
- 继续自建并迭代现有单文件界面（**否**）：每加一类数据要手工同步常量、脚本、测试、文档多处，已出现漏算第 10 表、schema 少拉 2 表、注释白名单缺项；三处副本靠人工命令一致，换账号曾导致旧数据取不回。
- 只读皮肤 + 现成服务作数据层（**未采纳**）：能保住审美，但仍引入需要托管的静态站点与凭证维护；留给 Q1 后置的形态决策，本 ADR 不锁死。
- 零代码现成服务 + 系统级提醒/日历（**采纳**）：PRD 第 7 节逐条打勾的全部满足项。

**Consequences**
- 3933 行的 `workbench_build/workbench.html` 与离线副本转为历史存档，不再作为交付物迭代；`docs/01`–`08` 降级为历史参考。
- 玻璃拟态 / Bento 视觉诉求不再由本项目满足；若将来用户明确保住审美，需重新打开形态决策，可能另立 ADR 取代本条。
- 「不丢」改由可恢复的全量快照保证，不再承诺多副本实时一致；快照须在账号权限正常时定期产出。
- 主动邮件通道只剩「截止提醒」一类，月更退回零点击呈现；这是工具能力受限的**未验证取舍**，未做 1 天真实试用，换工具时需复核。
- 本决策由用户答案独立推出；如后续某个验收条目被证伪，闸门重开，架构讨论才被激活。

## Part 5 · 失败复盘摘要（全文见 POSTMORTEM.md）

**结论**：项目做成了，需求没做成。4 期 / 3933 行 / 282 单测 / 111 集成测试全绿，但「低摩擦记录、自动出现、换平台不丢」三件真需求一件都没稳定成立。

**三个第一性误判**：① 把症状当原因（修叠显/手机按钮，根在 SDK 耦合的自绘前端）；② 把手段当目标（单文件/ES5/10 表/测试数成了交付物）；③ 把历史约束当需求（宿主 lint 的 `databaseId` 字面量要求被抄进 NFR，形态首日锁死）。

**九个不好用**（详见 POSTMORTEM.md 第 2 节）：离线空壳却承诺「缓存数据」｜换账号即 12607｜改一行代码 11 条命令三处人工同步｜加第 10 表漏改 3 处｜首期 65/65 通过仍线上白屏｜文档过期到给死链｜保存失败只报「稍等重试」｜忘了打开月更不来｜改名断一处构建链。

**测试为什么没救回来**：单测不是假的（jsdom + mock SDK 业务行为测试），但射程错位——约 73% DOM/文本/状态断言、约 21% 数据写回、**0 条**视觉/布局/权限/同步一致性断言；8 项真实故障中 3 项事后补回归、4 项至今无回归。

**七条教训**（按伤害排序）：PRD 正文禁止出现技术名词 ｜ 先验证现成服务的触发能力再谈自建 ｜ 单一主副本 + 可恢复快照，不追多副本实时一致 ｜ 加一类数据要改 N 处，第一次漏改就停 ｜ 测试对着真实故障面建 ｜ 改名前列影响面清单 ｜ UI 库救不了你（视觉只占 6%，85% 工程量在别处）。
