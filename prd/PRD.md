**锚句（逐字保留，全文不改写）**

> 不是「拥有一个个人工作台」，而是「让工作/学习/申请/简历证据能以最低摩擦被记下来，并在早上、日报、月更、截止前自动出现在眼前，且换设备、换账号、平台变更时不会丢」。

## 1. 一句话目标

见锚句。本文档只定义「什么算做到了」，不定义「长什么样、用什么做」。形态是另一个独立决策（Q1），本 PRD 不预设。

## 2. 场景与动线

| # | 时刻 | 触发 | 期望（零点击到达 + 内容已预先生成） |
|---|---|---|---|
| S1 | 早上工作前 | 打开一个约定位置 | 零点击看到今日重点、逾期、卡住、临近截止 |
| S2 | 随时 | 想到一件事 | 一次输入 + 一次确认就记下，不选分类、不事后重抄 |
| S4 | 晚间 | 要写日报 | 出两版：自用版全含；领导摘要不含学习与申请 |
| S6 | 月初 | 到月初 | 零点击看到已生成好的证据清单 + 按用途标记分组的证据段落（Q15=B） |
| S7 | 任何时候 | 想确认没丢 | 一次操作拿到完整可读的全量副本，且做过恢复演练 |
| R1 | 截止前 14 天内 | 到点主动 | 发一封提醒邮件（**唯一保留的主动通道**） |

「学习复盘」不再是独立场景，降为按用途标记筛选的周度回看（Q10）。原「工作过程」场景是功能清单，已删除（Q2）。场景卡编号沿用 `docs/01-需求文档.md:23-29` 的 1–7，保留 1/2/4/6/7。

## 3. 验收条目

每条必须能用「是/否」判定，禁止模糊形容词。

| AC | 判定标准 |
|---|---|
| AC-01 | 记一条 = 一次输入 + 一次确认；不需先选分类、不需先打开某个页面、不需事后在别处再抄一遍 |
| AC-02 | 同一个事实只存在一份；一条记录可同时带多个用途标记；同一内容不会被录两次 |
| AC-03 | 取任一带有「用于学习统计」或「用于简历」标记的记录生成两版日报：领导摘要中不含该记录内容，自用版含 |
| AC-04 | 一次操作内产出完整、开放格式、可读、可被别处导入的全量快照；且至少做过一次实际恢复演练并能读回 |
| AC-05 | 早上打开约定位置，零点击即可看到今日重点、逾期、卡住、临近截止四类内容 |
| AC-06 | 申请截止 14 天内且状态为进行中的条目被呈现，并按截止日倒计时分级（细则见第 10 节遗留项） |
| AC-07 | 月初产出「证据清单 + 按用途标记分组的证据段落」，可复制；不产出完整简历文件，不自动改写任何简历文档 |
| AC-08-A | 临近截止时，由外部服务主动发出一封提醒邮件 |
| AC-08-B | 月初零点击即可看到已生成好的证据清单；**不发邮件**（Q15=B 的净结果） |
| AC-09 | 只做 S1/S2/S4/S6/S7 五张场景卡；学习复盘为筛选式回看，不作为独立场景 |

## 4. 失败场景

| 失败 | 对应 AC | 判定 |
|---|---|---|
| 换设备 / 换账号 / 厂商停服 / 断网 → 取不到数据 | AC-04 | 副本须在权限正常时定期产出，不能等出事再导 |
| 忘了打开 → 月更看不到 | **AC-08-B 未覆盖** | 见第 5 节「已知妥协」 |
| 同一事实被记两次 | AC-02 | 应只有一份 |
| 私密内容混进领导摘要 | AC-03 | 领导摘要应不含 |
| 提醒邮件没发出 / 发错 | AC-08-A | 需有可查的发送记录或失败可见 |

## 5. 非目标

- 不做多人协作、权限体系（依据 `docs/01-需求文档.md:96`）。
- 不产出完整简历文件、不自动改写简历文档（Q8）。
- 不要求多份副本实时一致（Q7）。
- 不做手机推送（Q13 选 C，不含手机推送）。
- **不做自定义界面**：列为**待定**，不提前锁死（Q1 形态决策后置）。
- 「打开网页即用」「离线可写」「定期手动导出导入」等旧表述不再作为需求（证据附录 A-2、A-3）。

**已知妥协（必须写成受限妥协，不得写成设计偏好）**

1. 月更（S6 / AC-08-B）不主动推送，回到「忘了打开就看不到」。这正是 Q9 当初答「否」想甩掉的问题；它只在「截止提醒」上被解决，在「月更」上没有。
2. 收缩原因是外部服务的发送能力有开通门槛，属于**工具能力限制，不是用户不需要**（证据附录 A-4）。
3. 该取舍**未经真实试用验证**：Q3 原本约定「等用现成工具试过再定」，Q13 已接受 1 天试用，Q15=B 把它跳过了。后续换工具时应复核。
4. 主动邮件通道只剩 A（截止提醒）一类；同类提醒呈现不一致，未来接手者会困惑，已记入 `docs/adr/0001-不自建前端层.md` 的后果清单。

## 7. 零方案评估

定义：「不写任何代码」能否满足。逐条 AC 打勾；举证见附录 A。

| AC | 不写任何代码能否满足 | 举证 |
|---|---|---|
| AC-01 ~ AC-07 | 能 | 附录 A-4、A-6 |
| AC-08-A | 能 | 附录 A-4、A-7 |
| AC-08-B | 能（零点击呈现，非主动发信） | 附录 A-4 |
| AC-09 | 能 | 场景裁剪属范围决策，不需要实现 |

结论：9 类验收条目全部可在零代码前提下满足 → 按 Q1 与既定闸门规则，「只有零方案被证伪才进入架构讨论」的条件**未触发**，因此本 PRD 不激活技术架构讨论，形态决策由流程收敛为「不自建前端层」。该结论是本次从用户答案独立推出，不是沿用外部诊断结论。

**注意**：本评估是纸面可行性核对，不是验收。AC-08-A 的发送能力有开通门槛且未经真实试用，见第 5 节妥协 3。
