## 0. 目标

**PRD 锚句（逐字保留）**

> 不是「拥有一个个人工作台」，而是「让工作/学习/申请/简历证据能以最低摩擦被记下来，并在早上、日报、月更、截止前自动出现在眼前，且换设备、换账号、平台变更时不会丢」。

**用户本次补充的两条新目标**

1. **无痛记录**：自动读取 Orca / Workbuddy / Codex 的工作聊天记录，自动整理成工作日志，不用手动重录。
2. **自动日程**：与 AI 对话时自动识别关键日程信息，自动安排日程。

## 2. 数据模型（PRD Q14：三层，非分表）

**核心原则**：不是 4 张表，而是「**1 条记录 + 4 个用途标记**」。同一个事实只存一份，可同时带多个标记（Q6），业务类别只是查看时的筛选方式（Q14）。

**统一记录（一条）**

```jsonc
{
  "id": "rec_...",          // 唯一 ID
  "content": "……",          // 一句话事实
  "tags": ["work", "study", "apply", "resume"],  // 用途标记，可多个
  "status": "todo|doing|done|blocked",           // 可选，主要给 work/apply
  "deadline": "YYYY-MM-DD",                       // 可选，主要给 apply
  "source": null,                                 // 可选，来源溯源（P2 摄入）
  "created_at": "ISO8601",
  "updated_at": "ISO8601"
}
```

### 领域 × 功能矩阵（用户要求逐项细化）

| 领域(标记) | 记录时激活字段 | 触发场景 | 细化功能 |
|---|---|---|---|
| **工作 `work`** | 状态、截止日(可选) | S1 早安 / S2 随手记 / S4 日报 | ① 一句话记事项 ② 标卡住/阻塞 ③ 今日重点 ④ 逾期列表 ⑤ 两版日报（领导摘要=仅 work 且非私密） ⑥ 完成勾选 |
| **学习 `study`** | 主题(可选) | S2 / 周度回看 | ① 记学习内容 ② 周度回看（Q10 降级为筛选，非独立场景） ③ 进自用日报、**不进领导摘要** |
| **申请 `apply`** | 状态、**截止日(必填)** | S1 / S2 / R1 | ① 记申请目标+截止日 ② 截止 14 天内倒计时分级（≤3 / ≤7 / ≤14 天，AC-06/L1） ③ 临近截止进早安简报 ④ 可引用 resume 证据 |
| **简历证据 `resume`** | 证据段落 | S2 / S6 月更 | ① 记证据段落 ② 月初「证据清单+按用途分组段落」（AC-07） ③ 只出清单/段落，**不生成完整简历、不改写简历文件**（Q8） |

交叉例：一条「拿了 XX 竞赛一等奖」带 `apply + resume` 两个标记 → 既进申请材料、又进月更证据清单，只记一次。

## 3. 存储布局（D6：本地主副本 + Git 备份）

```
C:\Users\DC\workbench\          ← git 仓库，私有 GitHub 远端
├── records.jsonl               # 唯一主副本（追加式，一行一条）
├── snapshots\                  # AC-04 全量快照 + 恢复演练记录
├── reports\                    # 派生产物（今日简报/日报/月更证据，可随时重生成）
├── sources\                    # P2 三来源摄入的增量游标/缓存（来源日志只读不删）
└── docs\                       # 决策记录(ADR)/PLAN
```

- **主副本永远是本地开放格式文件**；每次快照时 `git commit + push` 做备份（备份 ≠ 实时一致，符合 Q7）。
- 数据主权靠「本地文件 + 可导出快照」，不靠「永不换平台」。

## 5. 三阶段执行计划

### P1 地基（先跑通 PRD 原 5 场景）

1. **决策记录**：`workbench/docs/ADR-0002-形态选择DSH.md`（记 L6 落地、R1 偏离、存储方案）。
2. **数据层**：`records.jsonl` + schema 校验（4 标记、去重键）。
3. **工具插件 v1** `@local/dsh-workbench`：
   - `record`（一次输入+确认+去重）
   - `list`（按标记·状态·截止·日期筛选）
   - `daily`（两版日报，AC-03）
   - `evidence`（月初证据清单+分组段落，AC-06/07）
   - `deadlines`（截止 14 天倒计时分级）
   - `snapshot`（全量快照+恢复演练，AC-04）
4. **persona 预设** `@local/dsh-personal-workbench`：锚句 + 5 场景 + 10 条 AC + 术语表（工作台/记录/用途标记/自动/不丢/证据 + `_Avoid_`）+ 领域矩阵行为规则（不选分类、不重抄、两版隔离、月更只出证据不出简历）。
5. **定时任务**：S1 每日 08:00 早安简报、S6 每月 1 日月更证据、R1 每日截止检查（定时投递）。
6. **验收**：AC-01~09 逐条跑「是/否」，重点 AC-03 两版隔离、AC-04 真实恢复演练、AC-05 零点击。

> 里程碑：PRD 10 条 AC 全过。

### P2 无痛记录（自动读三来源 → 工作日志）

1. **固定日志路径**：Codex `~/.codex/sessions/*.jsonl`、Orca（经 `orca` CLI 读 session，执行时用 `orca-cli` skill 确认命令）、Workbuddy `.workbuddy/memory/*.md`（三者均在 `C:\Users\DC` 内）。
2. **工具 `workbench_ingest(source)`**：读某来源增量 → LLM 提炼 → 去重 → 追加 `records.jsonl`（带 `source` 溯源）。
3. **触发**：每晚定时自动摄入 + 手动「整理今天的 Orca/Workbuddy/Codex」一键跑。
4. **验收**：三来源各跑一次真实摄入，去重/溯源正确，来源日志只读不删、主副本只增不删。

> 里程碑：三个来源都能自动整理成工作日志。

### P3 自动日程（对话识别 → 自动安排）

1. **第一版（轻量）**：persona 规则「识别到日程/截止/会议意图 → 自动 `schedule_create` 安排 + 记一条带标记的记录」。
2. **试用验证**识别准确率（漏检/误报）。
3. **第二版（可靠，可选）**：Host 插件挂 agent 回合结束钩子做常驻「日程抽取」。
4. **验收**：对话说「周五下午 3 点开会」→ 自动生成定时提醒 + 记录。

> 里程碑：日程自动识别并安排，无明显漏检。

## 6. 验收总表

| 项 | 判定标准 |
|---|---|
| AC-01~AC-09（PRD） | 逐条「是/否」，见 P1 验收 |

| 数据不丢 | 本地主副本 + 一次操作快照 + 至少一次真实恢复演练读回 |
| 隐私 | 摄入只读来源、不删来源；领导摘要不含 study/resume |
