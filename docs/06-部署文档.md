## 1. 部署架构

无服务器、无构建产物：唯一部署物是 `workbench_build/workbench.html`（单文件，约 193KB）。通过资料库导入链路上传并发布；离线版为其同步副本。

```
workbench_build/workbench.html ──import_html──> 资料库页面节点 ──publish──> 发布链接
        │                                                        │
        └────────── cp / 同步重放 ──────────> DC的个人工作台-离线版.html
```

## 5. 回滚

- **应用层**：git 历史 即 部署历史——checkout 任意历史版本 workbench.html，重走 §3 发布流程即可回滚线上
- **数据层**：设置视图导入历史 JSON 备份（formatVersion=3），与云端合并恢复
- 注意：回滚应用不影响云端 schema（向前兼容字段安全；删字段前必须确认旧版本不再引用）

## 6. 注意事项与已知坑

1. **import 前置门**：HTML 不得含第三方域名的 `<img>` 外链（图片需内嵌/平台托管）；本项目全内联 SVG，天然合规
2. **发布链接 headless 不可直接测**：headless 环境下发布链接会重定向到营销页——UX 实测走「本地 HTTP + mock SDK 注入」通道（ux_review.js 已内置）
3. **git 推送 TLS 间歇失败**：Windows schannel 偶发握手失败导致 push 挂起，统一用 `git -c http.version=HTTP/1.1 push` 降级 HTTP/1.1
4. **PAT**：fine-grained PAT 需勾选仓库授权 + Contents: Read and write；推送 URL 形如 `https://OOOHGOD:<PAT>@github.com/OOOHGOD/personal-workbench.git`
5. **离线版同步**：离线版与源文件**零定制差异**（离线降级逻辑内置于源文件，运行时探测 `__SMART_PAGE__` 自动降级）——直接 `cp workbench_build/workbench.html DC的个人工作台-离线版.html`，同步后复测（HTML_PATH 指向离线版跑单测）
6. **仓库边界**：仓库根的 client/server/migrations 等为另一 Cloudflare D1 实验的产物，部署本项目时不涉及、不提交
