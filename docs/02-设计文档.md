## 1. 总体架构

```
┌─────────────────────────────────────────────────────┐
│                  用户浏览器                          │
│  ┌───────────────────────────────────────────────┐  │
│  │  workbench.html（单文件，全内联 ES5 JS/CSS）  │  │
│  │                                               │  │
│  │  视图层(9 视图) ← 渲染函数 ← STATE ← db SDK   │  │
│  └──────────────┬────────────────────────────────┘  │
└─────────────────┼───────────────────────────────────┘
                  │ window.__SMART_PAGE__.database
                  ▼
┌─────────────────────────────────────────────────────┐
│        WorkBuddy 资料库（个人空间 90RRiESz…）       │
│   页面节点 Uo1qyjrSZ67qmecuVnAxXU（web 型）        │
│   └── 挂载 9 张云数据表（子节点）                  │
│   发布态：https://workbuddy.link/p/Uo1qyjrSZ67qmecuVnAxXU │
└─────────────────────────────────────────────────────┘
                  ▲
                  │ 人工同步（cp + 发布）
┌─────────────────┴───────────────────────────────────┐
│  离线副本「DC的个人工作台-离线版.html」（同源， │
│  SDK 缺失时降级为只读模式 + JSON 导入导出）        │
└─────────────────────────────────────────────────────┘
```

**设计决策：**

| 决策 | 理由 |
|---|---|
| 单文件 HTML，无构建链 | 零运维、秒开、git 友好、可直接导入资料库页面 |
| 全内联 ES5 JS | 资料库页面注入环境兼容性最好；lint 工具对 ES5 解析最稳 |
| 状态单向流：`loadData() → STATE → renderXxx() → DOM` | 渲染函数只读 STATE、互不调用，`refreshAll()` 统一刷新入口，避免级联渲染 |
| 每张表 databaseId 用字面量常量 | DSDK lint 要求每个 `db.*` 调用点可见 databaseId 字面量 |
| 离线版与在线版同源 + 少量差异文案 | 一套逻辑两形态，靠运行时探测 `__SMART_PAGE__` 降级 |

### 2.2 Schema 演进约定

- **服务端真源**：`workbench_build/schema_srv_*.json`（`fetch_schemas.py` 从云端拉取）
- **canonical 规范形**：`canonical_*.json`（`gen_canonical.py` 生成，lint_schema 的输入）
- **字段并集**：`schema_srv_merged.json`（9 表 63 字段，DSDK lint 的 `--schema-file` 输入）
- **改表流程**：先在云端改 schema → fetch_schemas.py 落盘 → gen_canonical.py 重生成 → 改 workbench.html → lint

### 2.3 关键数据约定

- 示例数据一律带 `是否示例=true`；渲染层打「示例」徽标，统计与报告排除
- 日期统一 ISO `YYYY-MM-DD` 字符串；`daysBetween(a,b) = b - a`（**倒计时必须 `daysBetween(todayStr(), deadline)`**，参数序反了会出现「剩 -3 天」）
- 备份格式 `formatVersion=3`：9 表全覆盖，IMPORT_KEYS 驱动导入
- select 选项缓存 `SCHEMA_OPTIONS` **以 databaseId 为一级键**分键存储——AI 表与学习表都有「类型」字段，按字段名全局存会互相覆盖触发 11607 错误

## 3. 前端模块设计

### 3.1 视图与导航

9 个视图：today / tasks / projects / research / notes / resources / reports / study / apply（另有 settings 维护视图）。

**导航分设备双形态：**

- 桌面（>767px）：左侧边栏完整列出全部视图（sidenav，分组：核心 / 第 2-4 期模块 / 维护）
- 手机（≤767px）：底部固定栏 **5 个主按钮**（今日/任务/学习/申请/更多）+ **「更多」上滑抽屉**（3 列网格收纳项目/调研/速记/资料/报告/设置）

抽屉状态机：

```
关闭 --点「更多」--> 打开 --点抽屉项/主按钮/空白区/「收起」--> 关闭
     <--再点「更多」--
```

- `DRAWER_VIEWS = {projects, research, notes, resources, reports, settings}`：当前视图属抽屉集合时，「更多」按钮保持高亮（active 联动）
- `aria-expanded` / `role="dialog"` 提供可访问性语义
- 该设计源于 UX 实测 P0：10 按钮 × min-width 62px ≈ 620px > 390px 视口，后 4 个视图被截断不可达

### 3.2 渲染管线

```
boot → fetchSchemas(9表, 填充 SCHEMA_OPTIONS) → loadData(9表并行 list)
     → autoPostpone(顺延扫描) → refreshAll() → bindNav()/bindEvents()
用户操作 → dbAdd/dbUpdate/dbDelete → loadData → refreshAll（回环）
```

- `refreshAll()` 依次调 13 个 renderXxx()，全部只读全局 `STATE`
- 弹窗（modal）为单例容器 `#modalBox`，各助手函数（openTaskModal 等）负责拼装表单，select 选项来自 `SCHEMA_OPTIONS[DB_XXX][field]`

### 3.3 学习/申请模块（第 3 期）

- `applyNearDeadline()`：截止 14 天内 + 状态进行中 → 今日视图提醒盒，按截止日排序
- `deadlineText(deadline)`（纯文本，供 Markdown 草稿）与 `deadlineHtml(deadline)`（带色 span：逾期红/今天橙/≤3 天黄）分离，避免草稿混入 HTML
- 报告隔离：`buildSelfDraft()` 含「六、个人学习与留学申请」段；`buildLeaderDraft()` 不含——私密内容不进领导摘要
- 转任务：学习/申请「下一步」→ 任务表新记录，分类自动带（学习→分类学习/申请→分类申请）

## 4. 关键时序

### 4.1 自动顺延（幂等）

```
loadData 完成 → 扫描任务表：计划日期 < 今天 且 未完成
  → dbUpdate(计划日期=今天, 顺延次数+1, 原计划日期=旧值)
  → 刷新后再次扫描无命中（幂等），刷新按钮连点不重复顺延
```

### 4.2 报告生成

```
点「生成日报」→ 读 STATE 各表 → 按今日/本周/上周过滤
  → buildSelfDraft()（含学习/申请段，示例数据排除）
  → buildLeaderDraft()（工作相关）
  → 双文本框展示，一键复制
```

## 5. 安全设计

- 所有用户数据拼入 innerHTML 前必须经 `esc()`（HTML 实体转义）
- 本地路径显示用 `esc()` 后输出；复制走 `navigator.clipboard`，失败降级提示手动复制
- 无外部 CDN/脚本引入，杜绝供应链注入面
