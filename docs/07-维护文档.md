## 2. 修改标准流程（重要）

```
改 workbench.html → node 语法检查 → 单测（194/194）
→ lint 三门 → UX 实测（改 UI 必跑）
→ import_html 重导入（--node-block-id + --databases 9 表）
→ publish_page 发布 → 发布产物复测
→ 离线版同步 + 复测 → git commit & push（HTTP/1.1）
```

**禁止跳步**：直接发布未过单测的 HTML；只改在线版不同步离线版。

## 3. 常见维护任务

### 3.1 加/改字段（schema 演进）
1. 云端资料库界面改表结构（或建新表）
2. `fetch_schemas.py` → `gen_canonical.py` 重落盘
3. 若是**新表**：workbench.html 加 `DB_XXX` 常量、`ALL_DBS`、视图/渲染/弹窗；seed 脚本与单测 seedData 补种子；备份 formatVersion 升版 + IMPORT_KEYS 扩容
4. 走 §2 标准流程

### 3.2 修复线上问题
定位（控制台报错/UX 实测 findings）→ 修复 → §2 全流程。**示例**：2026-10-19 手机导航 P0（10 按钮溢出 390px）→ 5 主按钮 + 更多抽屉 + 单测场景 19 → 重发布。

### 3.3 数据维护
- 示例数据被误清：`seed_samples_v3.py` 重灌（幂等）
- 数据异常：设置视图导出 JSON 排查 → 修数据（云端表界面直接改）→ `fetch_schemas.py` 不需要，重拉页面即生效

### 3.4 空间/账号迁移（低频高危）
参照 2026-10-19 经验：`rebuild_tables.py`（幂等复刻）→ `dbid_map.json` 重映射 ID → 重导入发布 → 全量回归。**先跑 rebuild_tables 确认幂等性再动线上。**

## 4. 已知坑速查表（血泪教训）

| 症状 | 根因 | 解法 |
|---|---|---|
| 11607 选项不存在（保存报错） | SCHEMA_OPTIONS 按字段名全局存，跨表同名字段（AI 表/学习表都有「类型」）互相覆盖 | 按数据库 ID 分键：`SCHEMA_OPTIONS[DB_XXX][field]` |
| 倒计时显示「剩 -3 天」 | `daysBetween(a,b)=b-a`，参数序写反 | 必须 `daysBetween(todayStr(), deadline)` |
| create_database 输出解析失败 | 输出 JSON 后附 `KS_USER_REPLY` 行 | 逐行找 `{` 开头的行再 json.loads |
| lint_database_sdk_usage 假死 | 不带 `--schema-file` 会阻塞读 stdin | 必带 `schema_srv_merged.json` |
| lint_page_quality PQ001/PQ005 报错 | 已知误报（ES5 正则括号配平误判 / esc 转义后仍报警） | `--ack "<原因>"` 声明放行 |
| git push 挂起/403 | schannel TLS 间歇失败 / PAT 缺权限 | `-c http.version=HTTP/1.1`；PAT 勾 Contents 写权限 |
| 发布链接 headless 测不了 | 重定向到营销页 | ux_review.js 本地 HTTP + mock SDK |
| create 页面脚本「失败」但表已建 | 输出解析误判 + 幂等 | 重跑幂等脚本复用已有表 |
| 单测点错行内按钮 | 列表排序后 nth 选择器漂移 | 用 `[data-id="xxx"]` 精确选择器 |
