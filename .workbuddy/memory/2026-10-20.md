## git 推送报 "Invalid username or token" 的真因（本机高发坑）

- 现象：API 用同一个令牌完全正常（`/repos/...` 返回 push/pull/admin=true），但 `git fetch/ls-remote` 一直报 `Invalid username or token. Password authentication is not supported for Git operations.`
- 真因：**Windows 凭据管理器里存在两条 git 条目**，git 实际认证命中了陈旧的那条
  - `git:https://github.com`（新，正确）
  - `git:https://OOOHGOD@github.com`（陈旧，仍存着已失效的旧 gho_ 令牌）
- 定位手法：`git ... credential fill` 只回第一条，看不出问题 → 必须 `cmdkey /list` 全量看（bash 下中文乱码，改用 **PowerShell** 跑 `cmdkey /list` 再正则筛 `git:`）
- 修法：`cmdkey /delete:"git:https://OOOHGOD@github.com"` 后即恢复。只留一条正确条目
- 新令牌存法（不落明文配置）：`printf 'protocol=https\nhost=github.com\nusername=OOOHGOD\npassword=<PAT>\n\n' | git -c "credential.helper=" -c credential.helper=wincred credential approve`
- 验证顺序：`ls-remote` → `fetch` → 确认 `behind=0 ahead=0`
